# Model-driven Monitor

Building → Model / TensorRT controls detection. Building → Label provides new model-scoped, human-confirmed appearance samples. Legacy registration data is kept on disk but is inactive: startup, camera creation and reconnection never restore legacy template/SAM2 trackers. Legacy registration and mask-preview APIs return HTTP 410; the new Label APIs are separate.

SAM2 on Monitor requires a ready, uploaded model deployed to that camera (directly or through a workflow). Upload alone does not activate inference. Without an active deployment, cameras continue streaming and recording without legacy SAM2 masks. The backend rejects legacy metadata and custom frames from inactive models/cameras; Monitor only draws SAM2 for model-tagged robot/rack tracks. Stopping the last deployment clears its Monitor objects immediately when the worker stops.

1. Export the trained YOLO11 **detection** model as a self-contained ONNX file:
   `yolo export model=best.pt format=onnx imgsz=640 batch=1 dynamic=False half=False nms=False`.
2. Upload `best.onnx`, verify class names and wait for `ready` (TensorRT FP16 build).
3. Choose cameras and click **Deploy lên Monitor**. “All cameras” includes subsequently registered cameras. Deployment is persisted in PostgreSQL `vision.monitor_model` and restored on backend startup.
4. A single shared custom detector can serve direct Monitor deployment and workflows using the same model. Conflicting models are rejected. Stopping direct deployment does not stop a workflow still using that model.

## Runtime

- GPU decode/NVMM → TensorRT `nvinfer` every frame → NvDCF → latest-only detection metadata.
- GPU RGBA surfaces are copied device-to-device before leaving the DeepStream buffer callback. Two independent latest-only CUDA workers run SAM2; each camera stays on one worker to protect its temporal memory. Image resize, normalization, inference and mask boundary extraction stay on the GPU; the CPU assembles boundary coordinates and serializes metadata.
- SAM2 image features are shared by tracks in the same frame. Temporal memory is isolated by camera, model generation and track identity. Saved Label tracks seed exact user-mask memories from original JPEGs decoded on GPU; they do not require a YOLO box. Non-reference detector tracks can still use box prompts. Geometry and negative-identity checks remain active.
- Fresh SAM2 polygons follow NvDCF boxes between SAM2 updates. This is bounded box-guided propagation, **not fresh SAM2 inference on every video frame**. Masks expire after 700 ms without valid SAM2 evidence; missing tracks are removed rather than held indefinitely.
- Each scheduled SAM2 frame is actually inferred, including stationary targets. NvDCF propagation never refreshes the timestamp of the original SAM2 evidence. `mask.observed_at/frame_id` describe that evidence; `mask.attached_at` describes the current box-guided placement.
- Predictor instances share an initialized model within each worker without rerunning setup for every new track. Appearance-rejected masks skip polygon construction; GPU boundary extraction uses one coordinate transfer. Each accepted object is published immediately, rather than waiting for every object in the frame to finish. Image resolution and the 700 ms maximum mask-evidence age remain unchanged.
- A live box prompt decodes once, then commits memory only after geometry and appearance verification. It does not encode an unverified prompt and run a second decoder on the same image. Subsequent frames use verified temporal memory; Label preview and embedding signatures are unchanged.
- Pending cameras keep their first queued turn while their frame is replaced by the newest one. This prevents a high-frame-rate camera being starved by scheduling on the timestamps of repeatedly replaced frames.
- The plain detection gate still requires confidence 0.50 to acquire and 0.30 to retain a track. For categories with a compatible positive Label gallery, fresh detections at the existing detector floor (0.25) can reach SAM2 after two consistent frames. These candidates remain hidden unless current-revision appearance verification succeeds; deleting the gallery cannot promote a weak candidate into an unverified detection. Tiny, stale and discontinuous boxes are still rejected.
- Detection/tracking uses TensorRT; SAM2 currently uses CUDA FP16/PyTorch, not a TensorRT SAM2 engine. FPS depends on GPU load, camera count and visible targets. Do not claim a fixed FPS from synthetic tests.
- `Robot_2001` / `AMR_2001` / `AGV_2001` classes can identify FMS robot 2001 and use existing calibrated, time-aligned FMS checks. A generic `robot` class keeps separate track IDs but cannot establish FMS identity. Renaming a class is not training identity recognition.

## Operations

### Model-scoped Label

1. Deploy the model, open **Building → Label**, select the model/camera, and capture a frozen GPU frame.
2. Draw a tight box; optionally add foreground/background clicks. Preview SAM2 and save only an accurate mask.
3. Choose **Thêm góc nhìn cho vật đã đăng ký** (or the Label card's **Thêm góc nhìn**). The Label/class are locked while adding views. Capture a new frame, box/correct SAM2, preview and **Lưu thêm góc nhìn**. Saving clears the frame but retains the selected identity, including when changing cameras. Different objects need **Vật khác / Label mới**. Register hard negatives with separate names for confusing backgrounds/objects.
4. Triplet training starts with at least two views of one identity and a different identity/negative. It learns a 512-dimensional appearance projection, shared by human-confirmed samples and live model detections. **It does not retrain YOLO's ONNX/TensorRT weights.** Retrain/export YOLO separately to improve missed detections or inherently wrong classes.
5. Categories with registered samples require appearance verification. The optional strict mode also requires Labels for categories with no samples. Rejected, ambiguous, stale or incompatible embeddings do not generate confirmed Monitor masks. Existing calibrated FMS checks remain in effect.

Saving a positive Label means **initialize that object's tracking from the user-confirmed mask**, not merely add an appearance template to wait for YOLO. Original JPEGs and exact masks become SAM2 memory anchors; up to two diverse views are selected by default, while all compatible embeddings participate in identity matching. A GPU-issued receipt whose source frame is still within 350 ms can initialize its exact mask directly. An older annotation is propagated onto a new GPU frame before publication; its old coordinates are never stamped as a new observation. Save replies distinguish `runtime_sync.activation.mode=mask_initialized` from `tracking_queued`.

Human-confirmed reference tracks retain their expected identity instead of switching to a close triplet winner. A raw similarity below 0.78, a strong explicit negative, or a competing identity with at least a 0.06 raw-score advantage still prevents acceptance. Unanchored detections keep the stricter 0.84 raw threshold and 0.02 margin, followed by the existing triplet checks. These similarities are not calibrated probabilities. Metadata reports `user_reference`, `user_gallery` or `triplet`. Adding positive views to an existing Label preserves live memory and its bounded identity cache; deleting samples, adding negative examples or introducing another identity invalidates cached identity decisions. Label-initiated tracks win duplicate claims over model guesses.

Each Monitor camera has **Label / Thêm góc nhìn**. The dialog opens the same GPU-backed editor on that camera; select an existing Label, obtain a fresh frame, box/correct SAM2 and save another view. Camera streams/tracking remain connected in the background. **Xem / xóa góc** shows paginated saved images and confirmed contours, with deletion of individual views as well as whole Labels. No detection is automatically saved as user training data.

The detector and CUDA SAM2 operate in separate latest-only loops; triplet updates use a background CUDA stream with bounded training batches. Saved geometry is exported with every compatible gallery revision and loaded into the GPU prompt manager per camera and Label. A successful save/delete/settings operation requests a worker reload and returns an applied revision when the runtime acknowledges it; if the worker is temporarily unavailable, the persisted revision remains valid and the watcher retries it. Position without a live tracker expires after 350 ms; reacquisition attempts are bounded to once per second. Transient appearance failures preserve verified memory for two inference attempts without committing uncertain masks. Confirmed loss, negative matches and explicit revocation clear display state.

`/api/models/{model_id}/labels` provides authenticated list/delete/settings and `/snapshot`, `/preview`, `/samples`. `GET /samples?label=…&limit=12&offset=0` lists saved views without embeddings; `GET /samples/{id}/image` serves the model-scoped JPEG and `DELETE /samples/{id}` deletes one view. All routes require a dashboard session. GPU-issued receipts bind samples to a camera and expire after three minutes; clients cannot submit embeddings. Re-saving the same receipt is idempotent. Samples/labels are isolated by uploaded model and SAM2 signature. Incompatible signatures require re-registration.

PostgreSQL tables: `vision.label_samples` and `vision.label_settings`; actions are logged to `workflow.logs`. SSD storage: `MODEL_LABELS_DIR` (default `backend/data/model_labels/{model_id}`) containing JPEG samples, atomic `gallery.json`, and the triplet projection checkpoint. The gallery includes `camera_id`, `frame_id`, `bbox` and `mask` alongside appearance vectors. All saved compatible embeddings participate in live matching; adding views no longer silently removes old views. Sample count has no application limit, but SSD/GPU capacity still applies. Triplet training retains bounded rotating batches. Deletion bumps the gallery revision and republishes before removing the image; stale matches are invalidated when the worker applies that revision. Save/delete/settings responses include `runtime_sync`: `applied` confirms the GPU gallery revision, `pending` means persistence succeeded but live acknowledgement failed, and `next_start` means there is no running deployment for that model. Reload wakes the watcher immediately; its 0.5-second polling interval remains a fallback, not the normal save path. Automatic detector guesses never become training samples. No legacy samples are imported automatically.

Saved Label prompts run before detector candidates; an overlapping accepted Label mask avoids a redundant detection decode. Track IDs remain stable when another view is added. Prompt-only tracks use `mask.source=sam2_live`. If an overlapping NvDCF track is bound while SAM2 verifies the object, its fresh positions can move the last mask between SAM2 results, up to 700 ms of evidence age. Binding never switches to an arbitrary replacement ID. If no tracker position is available, placement expires at 350 ms. `mask.observed_at/frame_id` always retain the actual SAM2 evidence time; `attached_at` records placement, not new inference. Original reference memories are used for reacquisition rather than blindly reprompting a box at the old position.

Appearance matching can still confuse visually indistinguishable objects; it is not a guarantee of identity. Measure detection/identity quality with representative annotated multi-camera video. Fresh evidence expires rather than displaying a plausible-looking ghost indefinitely. Mask rendering is a thin antialiased contour and translucent fill; GPU mask resolution is 640 pixels wide.

Monitor draws the latest NvDCF-positioned contours on video presentation callbacks where supported, without temporal easing or adding a video buffer. Canvas pixel density is capped at 2, contour corner rounding is bounded to 0.65 CSS pixels, and instance colors remain stable for a Label across cameras. Hidden Monitor tabs stop drawing but retain connections. A stalled video clears its overlay after 350 ms; stale mask evidence still expires at 700 ms and stale placement at 350 ms. A new `attached_at` never resets the age of SAM2 evidence. The `MASK …ms` badge reports the oldest displayed mask's evidence age, not camera-to-display latency. Browser video and DeepStream metadata do not yet share a verified capture timestamp, so presentation callbacks are not an exact frame-ID synchronization guarantee.

A single missing metadata object no longer immediately erases a still-fresh mask. A mask-less packet can bridge the previous shape only with the same verified identity, fresh position and continuous geometry. Missing packets never refresh timestamps. Explicit `revoked_track_ids`, removed Labels, changed model/generation, hidden outputs and confirmed loss clear overlays without waiting for expiry. Late results cannot revoke a newer user correction. Slow scheduling is not hidden by extending the 350 ms placement lifetime.

`GET /api/models` reports deployment, latest metadata age, SAM2 readiness/errors, valid mask count and inference duration per camera. Segmentation diagnostics include bounded `detector_candidates`, `verification_candidates`, `visible_labels` (AI output before downstream FMS checks), and `candidate_label` on rejected appearance matches. The Label gallery shows the selected camera's verification state separately from sample persistence. A saved Label does not guarantee a YOLO detection or an accepted match at a new viewpoint. Upload/deploy/stop APIs require a dashboard session. Deployment actions are logged in `workflow.logs`.

Latency diagnostics in each camera's `segmentation` include `queue_wait_ms` (age of the latest selected frame at worker start), `inference_ms` (worker processing), `end_to_end_ms` (DeepStream probe to SAM2 result, not camera exposure to screen), pending/replaced/expired frames, and actual backbone/decoder counts. Metadata arrival and browser canvas time must be measured separately. A canvas animation loop or box propagation rate is not a SAM2 inference FPS measurement.

Models and build logs: `VISION_MODELS_DIR` (default `backend/models/uploads`). SAM2 weights: `CUSTOM_SAM2_MODEL` (default `backend/models/sam2.1_t.pt`). Optional settings: `CUSTOM_SAM2_IMGSZ=640`, `CUSTOM_SAM2_MAX_TRACKS=32` (per worker), `CUSTOM_SAM2_WORKERS=2` (clamped to 1–2), `CUSTOM_SAM2_REFERENCE_VIEWS=2` (clamped to 1–3). Reference encodings have a bounded 48-entry cache per worker. Capacity overflow is visible in target/mask diagnostics; it does not silently move segmentation to CPU.

Deployment requires the CUDA/PyTorch/Ultralytics, CuPy, pyds and DeepStream components in the backend image. Pose detection remains disabled independently of this pipeline.
